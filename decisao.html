1. As correções de acessibilidade

Abaixo estão as correções feitas nas páginas em Bootstrap para garantir que a documentação oficial fosse adaptada às necessidades reais de acessibilidade e semântica do projeto.

Registro de correções de acessibilidade
Componente Problema Como se detectou Correção Onde está no código
Botão do menu O nome acessível estava em inglês ("Toggle navigation"). Painel Accessibility do F12 mostrando Name "Toggle navigation". Alterado para aria-label="Menu". No button com classe navbar-toggler.
Botão de fechar diálogo O nome acessível estava em inglês ("Close"). Painel Accessibility do F12 com o diálogo aberto. Alterado para aria-label="Fechar". No button com classe btn-close, no modal-header.
Título do diálogo A documentação usa h1, mas a página já possui um h1 no topo. Recomendação da documentação e validação do W3C. Alterado para h2, mantendo a classe visual h5. No h2 com classe modal-title.
Mensagens de erro As mensagens visuais não estavam ligadas aos campos na árvore de acessibilidade. Leitura da apostila (seção 2.10) sobre aria-describedby. Adicionado ids nas mensagens e aria-describedby nos inputs. Nos inputs (nome, email, termos) e nas divs invalid-feedback.
Diálogo (Modal) O validador do W3C acusava erro de aria-labelledby sem role. Erro no validador do W3C. Adicionado o atributo role="dialog" diretamente no HTML. Na div com classe modal fade.

Pendências declaradas:

  • Foco após erro: O foco continua no botão de enviar após a validação falhar. Levar o foco para o primeiro campo com erro exigiria um programa em JavaScript customizado.
  • Diálogo dinâmico: O diálogo só exibe os detalhes do açaí. Para que ele abra com as informações de outros produtos, seria necessário criar um programa que altere o conteúdo do modal dinamicamente.

2. O registro de decisão

Contexto

A AgroFeira precisa definir como será estilizada daqui para frente, especialmente porque a partir do encontro 11 o projeto será migrado para React. Temos duas bases prontas: a folha autoral, que pesa 4,8 kB de CSS, e o Bootstrap, que pesa 35,0 kB de CSS e adiciona um script de 25,2 kB (que faz o menu e o modal funcionarem, mas quebra caso o JavaScript seja desativado).

Opções consideradas

  • Folha autoral: Ganha em leveza (4,8 kB) e controle total do código, mas cobra mais tempo de escrita manual de CSS.
  • Bootstrap: Ganha em velocidade de prototipagem e componentes prontos (menu, modal, formulários), mas cobra 35 kB de CSS e 25,2 kB de JS, além de depender de scripts para funcionar.
  • Tailwind: Ganha em velocidade de estilização (utilitários direto no HTML), mas cobra a necessidade de um passo de build (ou uso de CDN) e a mistura de muita classe no HTML.

Decisão

Vou continuar usando a folha autoral (nossos arquivos CSS) para estilizar o projeto em React.

Consequências aceitas

  • Aceito o trabalho de escrever o CSS manualmente para novos componentes que o React exigir.
  • Aceito não ter os componentes prontos de JavaScript do Bootstrap (como o menu retrátil e o modal), tendo que recriá-los usando o próprio React.

O que me faria mudar de ideia

Mudaria de ideia se o projeto React exigisse dezenas de componentes complexos (como tabelas avançadas e calendários) em um prazo muito curto, onde a produtividade do Bootstrap superaria o tempo de customização.
